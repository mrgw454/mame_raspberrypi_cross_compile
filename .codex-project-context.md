Project context for future Codex sessions

- This repo is maintained upstream by someone else. Prefer minimal, local compatibility fixes over broad refactors.
- The user relies on this repo to cross-compile current upstream MAME for Raspberry Pi.
- The wrapper scripts [make-mame_raspberrypi_cross_compile-unified.sh](/home/ron/source/mame_raspberrypi_cross_compile/make-mame_raspberrypi_cross_compile-unified.sh) and [make-mame_raspberrypi_cross_compile-unified-qt6.sh](/home/ron/source/mame_raspberrypi_cross_compile/make-mame_raspberrypi_cross_compile-unified-qt6.sh) are the practical entrypoints on this machine and may contain important local customizations from prior assistant work.
- Two workflows matter:
  - Full clean rebuild of toolchain/sysroot/build inputs.
  - Reuse existing downloaded/build prerequisites and only refresh/build new MAME source.
- Upstream MAME changes frequently. Favor adaptive build logic over pinning assumptions to one MAME release.
- As of 2026-06-03, the Debian 13 `arm64` sysroot in this repo is Qt5-based, not Qt6-based.
  - `conf/packages_debian_13_trixie_arm64` includes `libqt5core5t64`, `libqt5gui5t64`, `libqt5widgets5t64`, and `qtbase5-dev`.
  - The repo README also references Qt5 packages.
- As of 2026-06-03, the Raspberry Pi target `rpi500` is Debian 13 `trixie` `arm64` and has Qt6 available.
  - `pkg-config --modversion Qt6Core` reports `6.8.2`.
  - `qmake6` exists on the Pi.
  - The default `moc` on the Pi still points to Qt5, so Qt6 builds should prefer Qt6-specific host tool resolution instead of assuming `moc`.
- Newer MAME `0.288` Linux build generation expects Qt6 for the SDL Qt debugger path (`qmake6`, Qt6 libs, Qt6 moc path), which conflicts with the current sysroot.
- Current local work has shifted toward a parallel Qt6 path rather than replacing the existing Qt5 path.
  - New environment suffix: `qt6`
  - New distro string: `debian_13_trixie_arm64_qt6`
  - New wrapper: [make-mame_raspberrypi_cross_compile-unified-qt6.sh](/home/ron/source/mame_raspberrypi_cross_compile/make-mame_raspberrypi_cross_compile-unified-qt6.sh)
  - New package list: [conf/packages_debian_13_trixie_arm64_qt6](/home/ron/source/mame_raspberrypi_cross_compile/conf/packages_debian_13_trixie_arm64_qt6)
- The Qt6 wrapper now supports explicit modes:
  - `--fresh` rebuilds the Qt6 environment from scratch, then builds MAME.
  - `--reuse` keeps the existing Qt6 tool environment and only rebuilds MAME.
  - `--auto` is the default and bootstraps the Qt6 environment only if it is missing.
- The Qt6 wrapper is intended to exist both in this repo and as a convenience copy in `$HOME/source-other/`.
- The compile step now detects Qt from the target sysroot via `pkg-config` and rewrites MAME's generated Qt makefiles to use target-sysroot include/lib flags plus an appropriate host `moc`, instead of relying on host Qt install paths.
- Important correction from 2026-06-03:
  - an earlier Qt6 run looked successful because the compile completed and an archive was produced
  - that result was a false positive because the top-level binaries in `build/src/mame/` were `x86_64`, not `aarch64`
  - the repo's whole purpose is real ARM cross-compilation, so any host `x86_64` result is a hard failure
- Current Qt6 ARM resolution path:
  - preserve the repo's existing cross-compile machinery and the older wrapper behavior
  - keep the Qt6 work isolated in the parallel `debian_13_trixie_arm64_qt6` environment
  - in [functions/compile](/home/ron/source/mame_raspberrypi_cross_compile/functions/compile), force the target-stage MAME build through MAME's `linux_x64` target with `CONFIG=release`
  - this is required because the plain cross-build path was falling into MAME's generated `config=debug` / `config=release` makefile sections, which link against `scripts/...` archives and can leave misleading host-built outputs
  - the desired target path is the generated `release64` configuration, which writes to `linux_gcc/bin/x64/Release/...` while still using the ARM cross compiler
  - final validation must check `build/src/mame/mame` with `file` and require `aarch64`
- As of 2026-06-03, a corrected Qt6 compile is in progress with that `linux_x64` + `CONFIG=release` fix applied.
